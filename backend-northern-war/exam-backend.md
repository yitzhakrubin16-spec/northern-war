# מבחן Backend — המערכה בצפון

## המערכה בצפון

במהלך יומיים עליכם לבנות שרת עבור משחק אסטרטגיה לשחקן יחיד מול המחשב. זהו תרחיש משחק דמיוני: השחקן מנהל את ישראל והמחשב מנהל את חיזבאללה. מטרת כל צד היא לכבוש את מפקדת היריב.

במבחן נבדקים תכנון בסיס הנתונים, טעינת מידע מקובץ, Express, API, ניהול מצב, בדיקות תקינות ואלגוריתמים. אין לבנות ממשק משתמש.

## הפרונט נתון מראש

אתם מקבלים פרויקט Frontend מוכן:

https://github.com/hananFr/frontend-northern-war

ניתן לראות כאן המחשה של המשחק המלא:

https://northern-war.netlify.app/

הפרונט הנתון הוא חלק מחוזה המבחן. עליכם לבנות את ה־API לפי הנתיבים, גופי הבקשות ומבני התשובות שמוגדרים במסמך זה, כך שלאחר חיבור כתובת השרת לפרונט יהיה אפשר לשחק במשחק מתחילתו ועד סופו.

<ul style="text-align: right;" dir="rtl">
<li>אין לשנות את מבנה הבקשות בפרונט כדי להתאים אותו לשרת שבניתם.</li>
<li>אין לשנות את מבנה התשובות שהוגדר במסמך.</li>
<li>מותר לעדכן בפרונט רק את כתובת השרת שאליה נשלחות הבקשות.</li>
<li>השרת חייב לאפשר CORS עבור הכתובת שממנה הפרונט רץ, לרבות Live Server בזמן הפיתוח.</li>
<li>יש לבדוק בפועל שאפשר לפתוח משחק, לבצע תור מלא, לרענן את הדף ולהמשיך את המשחק הקיים.</li>
<li>קוד הפרונט אינו חלק מההגשה ואינו מקבל ציון.</li>
</ul>

אתר ההמחשה נועד להציג את זרימת המשחק ואת התוצאה המצופה. המימוש שנבדק הוא השרת שלכם והיכולת שלו להפעיל את הפרונט שסופק.

## בחירת בסיס הנתונים

עליכם לבחור בעצמכם בסיס נתונים שמתאים לפרויקט ולחבר אותו לשרת. ניתן לבחור ב־Supabase/PostgreSQL, בסיס נתונים יחסי אחר או MongoDB.

לא ניתן מבנה טבלאות או collections מראש. עליכם להחליט:

<ul style="text-align: right;" dir="rtl">
<li>אילו נתונים נשמרים.</li>
<li>כיצד נשמרת המפה.</li>
<li>כיצד נשמר מצב של משחק פעיל.</li>
<li>כיצד מיוצגים מערכי שכנים ומצב הטריטוריות.</li>
<li>כיצד מונעים יצירת נתוני מפה כפולים בכל הפעלה של השרת.</li>
</ul>

ב־README יש להסביר בקצרה מדוע בסיס הנתונים שנבחר מתאים למבנה ולפעולות של המשחק. אין תשובה אחת נכונה, אך הנימוק צריך להתייחס לפרויקט ולא רק להיכרות או לנוחות אישית.

חובה לשמור את מצב המשחק בבסיס הנתונים. שמירה במשתנה או במערך בזיכרון השרת אינה מספיקה.

אינכם נבחנים על עדכון שדה פנימי בתוך אובייקט מקונן בבסיס הנתונים. לאחר פעולה חוקית מותר לקרוא את ישות ה־<code>game</code>, לעדכן אותה בקוד ולהחליף בבסיס הנתונים את כל הישות בגרסה המעודכנת. אין חובה להשתמש ב־nested update או לעדכן ישירות טריטוריה מסוימת בתוך המסמך השמור.

יש לשמור סודות ופרטי התחברות ב־`.env`. אין להעלות אותם ל־Git.

## קובץ המפה

תקבלו את `map.json`. כל איבר מתאר טריטוריה:

```json
{
  "id": 10,
  "name": "נהריה",
  "x": 24,
  "y": 45,
  "neighbors": [7, 13, 15],
  "startOwner": "player",
  "headquarters": false,
  "distanceFromComputerHQ": 3,
  "distanceFromPlayerHQ": 3
}
```

<ul style="text-align: right;" dir="rtl">
<li><code>neighbors</code> מכיל את מזהי הטריטוריות שמחוברות לטריטוריה.</li>
<li><code>startOwner</code> הוא <code>player</code> או <code>computer</code>.</li>
<li><code>headquarters</code> מסמן מפקדה. אם השדה חסר, ערכו <code>false</code>.</li>
<li><code>x</code> הוא המרחק באחוזים מהקצה השמאלי של תמונת המפה.</li>
<li><code>y</code> הוא המרחק באחוזים מהקצה העליון של תמונת המפה.</li>
<li>הנקודה <code>x, y</code> מייצגת את מרכז כרטיס הטריטוריה. כיוון ה־RTL של העמוד אינו משנה את משמעות הערכים.</li>
<li>יש לשמור את <code>x</code> ו־<code>y</code> כחלק מנתוני הטריטוריה.</li>
<li><code>distanceFromComputerHQ</code> הוא מספר הצעדים הקבוע מהטריטוריה למפקדת המחשב.</li>
<li><code>distanceFromPlayerHQ</code> הוא מספר הצעדים הקבוע מהטריטוריה למפקדת השחקן.</li>
</ul>

המרחקים כבר חושבו עבורכם. אין לחשב מסלולים או מרחקים בעצמכם.

בעת אתחול המערכת יש לבדוק אם נתוני המפה כבר קיימים בבסיס הנתונים. אם הם אינם קיימים, יש לקרוא את `map.json` ולשמור את כל הטריטוריות. אסור ליצור עותק נוסף של אותן טריטוריות בכל הפעלה.

יצירת משחק חדש תשתמש במפה שנקראה מבסיס הנתונים ולא תייבא מחדש את ה־JSON ישירות למצב המשחק.

## יצירת משחק

<ul style="text-align: right;" dir="rtl">
<li>כל טריטוריה רגילה מתחילה עם 4 חיילים.</li>
<li>כל מפקדה מתחילה עם 8 חיילים.</li>
<li>ביירות היא מפקדת המחשב.</li>
<li>ירושלים היא מפקדת השחקן.</li>
<li>השחקן מתחיל.</li>
<li>מספר הסיבוב מתחיל ב־1.</li>
<li>השלב הראשון הוא <code>reinforce</code>.</li>
<li>מצב המשחק הוא <code>playing</code> והמנצח הוא <code>null</code>.</li>
</ul>

### מבנה מצב המשחק

מצב משחק שנשמר בבסיס הנתונים ומוחזר מהשרת חייב לכלול לפחות:

```js
{
  playerName: "Dana",
  round: 1,
  phase: "reinforce",
  status: "playing",
  winner: null,
  territories: []
}
```

<ul style="text-align: right;" dir="rtl">
<li><code>playerName</code> — שם השחקן שהתקבל ביצירת המשחק.</li>
<li><code>round</code> — מספר הסיבוב הנוכחי.</li>
<li><code>phase</code> — השלב הנוכחי בתור השחקן: <code>reinforce</code>, <code>attack</code> או <code>move</code>.</li>
<li><code>status</code> — <code>playing</code> או <code>finished</code>.</li>
<li><code>winner</code> — <code>player</code>, <code>computer</code> או <code>null</code> כל עוד המשחק לא הסתיים.</li>
<li><code>territories</code> — המפה במצבה הנוכחי. כל טריטוריה כוללת את נתוני המפה המקוריים, ובנוסף <code>owner</code> ו־<code>soldiers</code>.</li>
</ul>

אין צורך בשדה <code>currentPlayer</code>. תור המחשב מתבצע במלואו בשרת לאחר <code>move</code> או <code>end-turn</code>, ולא נשמר כתור שממתין לפעולת משתמש.

מזהה המשחק נוצר על ידי בסיס הנתונים ומוחזר בתשובת ה־API. הוא אינו חייב להישמר פעם נוספת בתוך אובייקט מצב המשחק.

## סדר התור

תור השחקן:

```text
reinforce → attack (תקיפה או דילוג) → move או end-turn
```

לאחר `move` או `end-turn`, המחשב מבצע תור מלא. בסיום תור המחשב:

<ul style="text-align: right;" dir="rtl">
<li>מגדילים את מספר הסיבוב ב־1.</li>
<li>מחזירים את השלב ל־<code>reinforce</code>.</li>
<li>מחזירים את השליטה לשחקן.</li>
</ul>

אסור לבצע פעולה שאינה שייכת לשלב הנוכחי.

### חיזוק

<ul style="text-align: right;" dir="rtl">
<li>השחקן בוחר טריטוריה אחת בבעלותו.</li>
<li>מוסיפים לו בדיוק 3 חיילים.</li>
<li>אי אפשר לפצל את החיזוק.</li>
<li>לאחר החיזוק עוברים ל־<code>attack</code>.</li>
</ul>

תקיפה חוקית רק כאשר:

<ol style="text-align: right;" dir="rtl">
<li>המקור שייך לשחקן.</li>

### העברת כוחות

השחקן רשאי להעביר כוחות פעם אחת או לדלג.

העברה חוקית רק כאשר:

<ol style="text-align: right;" dir="rtl">
<li>המקור והיעד שייכים לשחקן.</li>
<li>המקור והיעד שונים.</li>
<li>נשלח מספר שלם של חיילים.</li>
<li>נשלח לפחות חייל אחד.</li>
<li>נשאר לפחות חייל אחד במקור.</li>
<li>היעד נמצא ב־<code>neighbors</code> של המקור.</li>
</ol>

כל העברה היא לטריטוריה שכנה בלבד.

## אלגוריתם הקרב

```js
attackLuck = 0.6 + Math.random() * 0.4;
defenseLuck = 0.6 + Math.random() * 0.4;

attackPower = sentSoldiers * attackLuck;
defensePower = defendingSoldiers * defenseLuck;
```

<ul style="text-align: right;" dir="rtl">
<li>התוקף מנצח רק כאשר <code>attackPower > defensePower</code>.</li>
<li>בכל מצב אחר, כולל שוויון, המגן מנצח.</li>
<li>החיילים שנשלחו מופחתים מהמקור בכל תוצאה.</li>
</ul>

אם התוקף ניצח:

```js
survivors = Math.max(
  1,
  Math.ceil(sentSoldiers * (attackPower - defensePower) / attackPower)
);
```

היעד עובר לבעלות התוקף ונשארים בו `survivors` חיילים.

אם המגן ניצח:

```js
survivors = Math.max(
  1,
  Math.ceil(defendingSoldiers * (defensePower - attackPower) / defensePower)
);
```

הבעלות אינה משתנה וביעד נשארים `survivors` חיילים.

כיבוש מפקדה מסיים את המשחק מיד. אין להמשיך את התור לאחר כיבוש מפקדה.

## אלגוריתם המחשב

תור המחשב:

```text
חיזוק → תקיפה אפשרית → העברה אפשרית
```

אסור לבחור פעולות אקראיות. יש לממש את סדר העדיפויות הבא.

### הגדרות עזר

טריטוריית גבול היא טריטוריה של המחשב שיש לה לפחות טריטוריה שכנה אחת של השחקן.

### בחירת חיזוק

מוצאים את הערך הנמוך ביותר של `distanceFromComputerHQ` מבין הטריטוריות של השחקן.

אם המרחק הוא 2 או פחות, המחשב נמצא במצב הגנה. בוחרים טריטוריית גבול לפי:

<ol style="text-align: right;" dir="rtl">
<li>הערך הנמוך ביותר של <code>distanceFromComputerHQ</code>.</li>
<li>אם כמה טריטוריות נמצאות באותו מרחק — מספר החיילים הנמוך ביותר.</li>
<li>אם עדיין יש שוויון — ה־<code>id</code> הנמוך ביותר.</li>
</ol>

אם המרחק גדול מ־2, המחשב נמצא במצב התקפה. בוחרים טריטוריית גבול לפי:

<ol style="text-align: right;" dir="rtl">
<li>הערך הנמוך ביותר של <code>distanceFromPlayerHQ</code>.</li>
<li>מספר החיילים הגבוה ביותר.</li>
<li>ה־<code>id</code> הנמוך ביותר.</li>
</ol>

לטריטוריה שנבחרה מוסיפים בדיוק 3 חיילים.

### בחירת תקיפה

המחשב פועל לפי הכללים הבאים:

<ol style="text-align: right;" dir="rtl">
<li>אם המחשב יכול לתקוף ישירות את מפקדת השחקן, ומספר החיילים שהוא יכול לשלוח גדול ממספר החיילים במפקדה, הוא מעדיף את התקיפה הזאת על פני כל תקיפה אחרת.</li>
<li>נגד טריטוריה רגילה המחשב שוקל תקיפה רק כאשר מספר החיילים שהוא יכול לשלוח גדול לפחות ב־35% ממספר המגינים.</li>
<li>מבין התקיפות האפשריות המחשב מעדיף תקיפה שמקדמת אותו לעבר מפקדת השחקן ושבה יתרון החיילים שלו גדול יותר.</li>
<li>טריטוריה של השחקן שנמצאת קרוב למפקדת המחשב מקבלת עדיפות נוספת, כדי שהמחשב ינסה להסיר איום על מפקדתו.</li>
<li>אם אין תקיפה שעומדת בתנאים, המחשב אינו חייב לתקוף וממשיך לשלב העברת הכוחות.</li>
</ol>

עבור כל מקור של המחשב ויעד שכן של השחקן:

```js
// מספר החיילים שהמחשב יכול לשלוח תוך השארת חייל אחד בטריטוריית המקור.
sentSoldiers = from.soldiers - 1;

// היחס בין הכוח התוקף למספר החיילים שמגינים על טריטוריית היעד.
advantageRatio = sentSoldiers / to.soldiers;
```

תקיפה נגד טריטוריה רגילה היא מועמדת רק כאשר:

```js
advantageRatio >= 1.35
```

אם היעד הוא מפקדת השחקן, התקיפה היא מועמדת כאשר:

```js
sentSoldiers > to.soldiers
```

לכל מועמדת לתקיפת המחשב:

```js
// התקדמות: האם תקיפת היעד מקרבת את המחשב למפקדת השחקן.
// התוצאה היא 1 בהתקרבות, 0 ללא שינוי ו־1- בהתרחקות.
progress = from.distanceFromPlayerHQ
  - to.distanceFromPlayerHQ;

// יתרון החיילים: ככל שנשלחים יותר חיילים ביחס למגינים, הציון גבוה יותר.
soldierAdvantage = sentSoldiers - to.soldiers;

// הגנת המפקדה: תקיפת טריטוריה שמאיימת על מפקדת המחשב מקבלת בונוס.
protectsHeadquarters = Math.max(
  0,
  3 - to.distanceFromComputerHQ
) * 25;

// התקדמות: תקיפה שמתקרבת למפקדת השחקן מקבלת משקל של 10 נקודות לצעד.
progressScore = progress * 10;

// כיבוש המפקדה הוא היעד החשוב ביותר ולכן מקבל בונוס גבוה במיוחד.
headquartersScore = to.headquarters ? 1000 : 0;

// הציון הסופי מחבר את כל סדרי העדיפויות של המחשב.
score = progressScore
  + soldierAdvantage
  + protectsHeadquarters
  + headquartersScore;
```

`progress` ו־`soldierAdvantage` מחוברים לאותו ציון: הראשון מעדיף התקדמות לעבר מפקדת השחקן, והשני מעדיף קרב שבו למחשב יתרון גדול יותר. הכפלה ב־10 נותנת עדיפות להתקדמות, בלי לבטל את השפעת יתרון החיילים.

הבונוס `protectsHeadquarters` נותן עדיפות לפעולה שמרחיקה איום ממפקדת המחשב. יעד שהוא מפקדת השחקן מקבל עדיפות עליונה.

המחשב מבצע את התקיפה בעלת הציון הגבוה ביותר ושולח את כל החיילים מלבד אחד.

בשוויון בוחרים יעד בעל `id` נמוך יותר, ולאחר מכן מקור בעל `id` נמוך יותר.

אם אין מועמדת שעוברת את סף `1.35`, המחשב אינו תוקף.

### העברת כוחות של המחשב

לאחר התקיפה המחשב בודק את כל זוגות הטריטוריות השכנות שבבעלותו. מקור חוקי חייב:

<ol style="text-align: right;" dir="rtl">
<li>להיות בבעלות המחשב.</li>
<li>להיות שונה מהיעד.</li>
<li>להיות ללא שכן בבעלות השחקן.</li>
<li>להכיל יותר מחייל אחד, או יותר מ־4 אם הוא מפקדה.</li>
</ol>

אם המחשב נמצא במצב הגנה, מעבר הוא מועמד רק כאשר:

```js
to.distanceFromComputerHQ < from.distanceFromComputerHQ
```

אם המחשב נמצא במצב התקפה, מעבר הוא מועמד רק כאשר:

```js
to.distanceFromPlayerHQ < from.distanceFromPlayerHQ
```

בוחרים מעבר לפי הסדר הבא:

<ol style="text-align: right;" dir="rtl">
<li>המקור בעל מספר החיילים הגבוה ביותר.</li>
<li>אם יש כמה מעברים שמקורם מכיל אותו מספר חיילים — בוחרים מביניהם את המעבר שהיעד שלו בעל ה־<code>id</code> הנמוך ביותר.</li>
<li>אם לשני מעברים מועמדים יש גם אותו יעד — בוחרים את המקור בעל ה־<code>id</code> הנמוך ביותר.</li>
</ol>

מטריטוריה רגילה מעבירים את כל החיילים מלבד אחד. ממפקדה מעבירים את כל החיילים מלבד ארבעה. אם אין מקור חוקי, לא מתבצעת העברה.

## API נדרש

כל ה־endpoints מקבלים ומחזירים JSON, מלבד בקשה שאין לה גוף. מזהה המשחק בנתיב הוא המזהה שנוצר בבסיס הנתונים.

### מבנה תשובה של פעולה

ה־endpoints של חיזוק, תקיפה, העברה וסיום תור מחזירים:

```json
{
  "game": {
    "id": "game-id",
    "playerName": "Dana",
    "round": 2,
    "phase": "reinforce",
    "status": "playing",
    "winner": null,
    "territories": []
  },
  "playerEvent": null,
  "computerEvents": []
}
```

<ul style="text-align: right;" dir="rtl">
<li><code>game</code> הוא מצב המשחק המלא לאחר הפעולה.</li>
<li><code>playerEvent</code> מתאר את הפעולה שביצע השחקן. בדילוג על תקיפה או בסיום תור ללא העברה ערכו <code>null</code>.</li>
<li><code>computerEvents</code> הוא מערך הפעולות שביצע המחשב. לפני תור המחשב הוא ריק.</li>
</ul>

אירוע חיזוק כולל `type`,‏ `territoryId` ו־`soldiersAdded`. אירוע העברה כולל `type`,‏ `fromId`,‏ `toId` ו־`soldiers`. אירוע תקיפה כולל לפחות `type`,‏ `fromId`,‏ `toId`,‏ `soldiers` ו־`winner`.

### `POST /games` — יצירת משחק חדש

מטרת ה־endpoint היא ליצור משחק חדש ולהחזיר את מצבו ההתחלתי.

גוף הבקשה:

```json
{ "playerName": "Dana" }
```

<ul style="text-align: right;" dir="rtl">
<li><code>playerName</code> חייב להיות טקסט שאינו ריק. יש להסיר רווחים מיותרים מתחילתו ומסופו.</li>
<li>השרת קורא את המפה מבסיס הנתונים, יוצר עותק שלה עבור המשחק ומוסיף לכל טריטוריה <code>owner</code> ו־<code>soldiers</code>.</li>
<li>המשחק מתחיל בסיבוב 1, בשלב <code>reinforce</code> ובמצב <code>playing</code>.</li>
<li>השרת שומר את המשחק בבסיס הנתונים.</li>
</ul>

תגובה תקינה: `201 Created` ומצב המשחק המלא, כולל המזהה שנוצר:

```json
{
  "id": "game-id",
  "playerName": "Dana",
  "round": 1,
  "phase": "reinforce",
  "status": "playing",
  "winner": null,
  "territories": []
}
```

אם שם השחקן חסר או ריק, מחזירים `400 Bad Request` ולא יוצרים משחק.

### `GET /games/:id` — טעינת משחק

מטרת ה־endpoint היא לקבל משחק קיים מבסיס הנתונים, למשל לאחר רענון הדף.

<ul style="text-align: right;" dir="rtl">
<li><code>:id</code> הוא מזהה המשחק שנוצר על ידי בסיס הנתונים.</li>
<li>אין גוף בקשה.</li>
<li>אין לשנות את מצב המשחק במהלך הבקשה.</li>
</ul>

תגובה תקינה: `200 OK` ומצב המשחק המלא באותו מבנה שמוחזר מיצירת משחק.

אם לא נמצא משחק בעל המזהה שנשלח, מחזירים:

```json
{ "error": "המשחק לא נמצא" }
```

עם הסטטוס `404 Not Found`.

### `POST /games/:id/reinforce` — חיזוק טריטוריה

מטרת ה־endpoint היא לבצע את שלב החיזוק של השחקן.

גוף הבקשה:

```json
{ "territoryId": 13 }
```

<ul style="text-align: right;" dir="rtl">
<li>המשחק חייב להיות פעיל ובשלב <code>reinforce</code>.</li>
<li><code>territoryId</code> חייב לזהות טריטוריה בבעלות השחקן.</li>
<li>השרת מוסיף לטריטוריה בדיוק 3 חיילים ומשנה את השלב ל־<code>attack</code>.</li>
<li>לאחר הצלחה השרת שומר את מצב המשחק המעודכן.</li>
</ul>

תגובה תקינה: `200 OK` במבנה תשובת הפעולה. `playerEvent` מתאר את החיזוק ו־`computerEvents` הוא מערך ריק, משום שתור המחשב עדיין לא התחיל.

### `POST /games/:id/attack` — תקיפה או דילוג על תקיפה

מטרת ה־endpoint היא לבצע את שלב התקיפה היחיד של השחקן או לדלג עליו.

כדי לתקוף שולחים:

```json
{ "fromId": 10, "toId": 7, "soldiers": 5 }
```

<ul style="text-align: right;" dir="rtl">
<li><code>fromId</code> הוא מזהה טריטוריית המקור של השחקן.</li>
<li><code>toId</code> הוא מזהה טריטוריית יעד שכנה בבעלות המחשב.</li>
<li><code>soldiers</code> הוא מספר החיילים שנשלחים לקרב.</li>
<li>המשחק חייב להיות פעיל ובשלב <code>attack</code>.</li>
<li>השרת בודק בעלות, שכנות, מספר חיילים שלם וחיובי והשארת חייל אחד לפחות במקור.</li>
<li>השרת מפעיל את אלגוריתם הקרב. אם נכבשה מפקדה, המשחק מסתיים מיד. אחרת השלב משתנה ל־<code>move</code>.</li>
</ul>

כדי לדלג על התקיפה שולחים לאותו endpoint:

```json
{ "skip": true }
```

דילוג מותר רק בשלב `attack`. במקרה זה לא מתבצע קרב, `playerEvent` הוא `null` והשלב משתנה ל־`move`.

תגובה תקינה: `200 OK` במבנה תשובת הפעולה. בתקיפה `playerEvent` מתאר את הקרב; בדילוג ערכו `null`. בשני המקרים `computerEvents` עדיין ריק.

### `POST /games/:id/move` — העברת כוחות וסיום תור השחקן

מטרת ה־endpoint היא לבצע העברת כוחות אחת ולסיים את תור השחקן.

גוף הבקשה:

```json
{ "fromId": 17, "toId": 14, "soldiers": 3 }
```

<ul style="text-align: right;" dir="rtl">
<li><code>fromId</code> ו־<code>toId</code> חייבים לזהות שתי טריטוריות שכנות ושונות בבעלות השחקן.</li>
<li><code>soldiers</code> חייב להיות מספר שלם וחיובי, ולאחר ההעברה חייב להישאר לפחות חייל אחד במקור.</li>
<li>המשחק חייב להיות פעיל ובשלב <code>move</code>.</li>
<li>לאחר ההעברה השרת מפעיל תור מחשב מלא: חיזוק, תקיפה אפשרית והעברה אפשרית.</li>
<li>אם המשחק לא הסתיים, השרת מגדיל את מספר הסיבוב ומחזיר את השלב ל־<code>reinforce</code>.</li>
</ul>

תגובה תקינה: `200 OK` במבנה תשובת הפעולה. `playerEvent` מתאר את העברת השחקן ו־`computerEvents` מכיל את הפעולות שביצע המחשב לפי סדר ביצוען.

### `POST /games/:id/end-turn` — סיום תור ללא העברה

מטרת ה־endpoint היא לאפשר לשחקן לוותר על העברת כוחות ולסיים את תורו.

<ul style="text-align: right;" dir="rtl">
<li>אין גוף בקשה.</li>
<li>המשחק חייב להיות פעיל ובשלב <code>move</code>.</li>
<li>לא מתבצעת פעולת שחקן נוספת.</li>
<li>השרת מפעיל תור מחשב מלא.</li>
<li>אם המשחק לא הסתיים, מספר הסיבוב גדל והשלב חוזר ל־<code>reinforce</code>.</li>
</ul>

תגובה תקינה: `200 OK` במבנה תשובת הפעולה. `playerEvent` הוא `null` ו־`computerEvents` מכיל את פעולות המחשב.

### שגיאות ושמירת מצב

<ul style="text-align: right;" dir="rtl">
<li>משחק שלא נמצא מחזיר <code>404 Not Found</code>.</li>
<li>משחק שכבר הסתיים מחזיר <code>409 Conflict</code> בכל ניסיון לבצע פעולה נוספת.</li>
<li>שלב שגוי, טריטוריה לא חוקית או מספר חיילים לא חוקי מחזירים <code>400 Bad Request</code> עם <code>{ "error": "הסבר ברור" }</code>.</li>
<li>שגיאה בלתי צפויה מחזירה <code>500 Internal Server Error</code>.</li>
<li>בדיקות התקינות, הקרב ותור המחשב מתבצעים בשרת בלבד.</li>
<li>לאחר פעולה חוקית יש לשמור את המצב המעודכן בבסיס הנתונים. לאחר פעולה לא חוקית אין לשנות את המצב השמור.</li>
</ul>

שמירת המצב המעודכן יכולה להתבצע באמצעות החלפה מלאה של ישות ה־<code>game</code>. החלפה מלאה נחשבת מימוש תקין ואינה גוררת הפחתת נקודות.

## בדיקות חובה

יש לכתוב בדיקות ללוגיקת המשחק בלי להתחבר לבסיס נתונים אמיתי.

יש לבדוק לפחות:

<ol style="text-align: right;" dir="rtl">
<li><strong>הגנה על מפקדת המחשב:</strong> משנים את צידון, שמזהה ה־<code>id</code> שלה הוא 4, לבעלות השחקן ונותנים לה 10 חיילים. לאחר הפעלת תור המחשב, פעולת החיזוק הראשונה צריכה להוסיף 3 חיילים לביירות, שמזהה ה־<code>id</code> שלה הוא 2.</li>
<li><strong>כיבוש ישיר של מפקדת השחקן:</strong> משנים את עפולה, שמזהה ה־<code>id</code> שלה הוא 16, לבעלות המחשב ונותנים לה 20 חיילים. בירושלים משאירים 3 חיילים. לאחר הפעלת תור המחשב, יעד התקיפה צריך להיות ירושלים, שמזהה ה־<code>id</code> שלה הוא 17, והמשחק צריך להסתיים בניצחון המחשב.</li>
<li><strong>תור ללא תקיפה:</strong> נותנים 20 חיילים לכל טריטוריה בבעלות השחקן. לאחר הפעלת תור המחשב, צריכה להופיע פעולת חיזוק אך לא צריכה להופיע פעולת תקיפה.</li>
<li><strong>העברה מטריטוריה עורפית בלבד:</strong> במצב הפתיחה המחשב אמור לבצע העברה. לפני הפעלת תור המחשב שומרים את מזהי כל הטריטוריות של המחשב שאין להן טריטוריה שכנה בבעלות השחקן. לאחר התור מוודאים שקיימת פעולת העברה ושמזהה טריטוריית המקור שלה מופיע ברשימה שנשמרה.</li>
</ol>
