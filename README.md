# northern-war

## בסיסי נתונים

### Map וgames

השתמשתי ב MongoDB משום שמבנה הנתונים הדינמי עוזר לנהל יותר טוב את השינויים בטריטוריות ומצבי המשחק




## Endpoints

### `POST /games` - יצירת משחק חדש

מקבל body

```json
{ "playerName": "שם השחקן" }
```

מסיר רווחים מתחילת וסוף השם
השרת קורא את המפה מהטבלא יוצר עותק עבור המשחק עם owner וsoldiers לכל טריטוריה
מתחיל את המשחק בסיבוב 1, סטטוס playing ושלב reinforce
שומר את המשחק בבסיס הנתונים

תגובה 201 created

ומצב המשחק עם המזהה שלו

אם שם השחקן ריק 400 Bad Request ולא יוצר משחק

סטטוס: עובד
### `GET /games/:id` - טעינת משחק

מחזיר משחק קיים לפי הid
 סטטוס 200 OK

 אם לא נמצא מחזיר 
 ```json
 { "error": "המשחק לא נמצא" }
```

סטטוס 404 Not Found

סטטוס: עובד

### `POST /games/:id/reinforce` - חיזוק טריטוריה

מקבל body
לדוגמא:
```json
{ "territoryId": 15 }
```

בודק שהמשחק פעיל ובשלב reinforce
מוודא שהטירטוריה שבגוף הבקשה בבעלות השחקן
מוסיף 3 חיילים בדיוק ומשנה מצב לattack
שומר את המצב המעודכן

מחזיר 200 OK 

סטטוס: עובד

### `POST /games/:id/attack ` - תקיפה או דילוג על תקיפה


מקבל body
לדוגמא:
```json
{ "fromId": 10, "toId": 7, "soldiers": 5 }

```

מוודא שהמשחק פעיל ובשלב attack
בודק בעלות על טריטוריית המקור, שכנות לטריטוריית היעד, שמספר החיילים שלם וחיובי ושנשאר לפחות חייל אחד במקור

השרת מפעיל את אלגוריתם הקרב
אם נכבשה מפקדה המשחק מסתיים
אחרת המצב משתנה לmove

כדי לדלג על התקיפה שולחים body כזה
```json
{ "skip": true }
```

דילוג מותר רק בשלב attack. במקרה זה לא מתבצע קרב, playerEvent הוא null והשלב משתנה ל־move.

תגובה תקינה: 200 OK במבנה תשובת הפעולה. בתקיפה playerEvent מתאר את הקרב; בדילוג ערכו null. בשני המקרים computerEvents עדיין ריק.

סטטוס: עובד בשרת
נתקע בפרונט
### `POST /games/:id/move` - העברת כוחות וסיום תור השחקן


מקבל body
לדוגמא:
```json
{ "fromId": 17, "toId": 14, "soldiers": 3 }
```

מוודא שהמשחק פעיל ובשלב move
בודק בעלות על טריטוריית המקור, שכנות לטריטוריית היעד, שמספר החיילים שלם וחיובי ושנשאר לפחות חייל אחד במקור


לאחר ההעברה השרת מפעיל תור מחשב מלא: חיזוק, תקיפה אפשרית והעברה אפשרית.

אם המשחק לא הסתיים, השרת מגדיל את מספר הסיבוב ומחזיר את השלב ל־reinforce.

תגובה תקינה: 200 OK במבנה תשובת הפעולה. playerEvent מתאר את העברת השחקן ו־computerEvents מכיל את הפעולות שביצע המחשב לפי סדר ביצוען.


סטטוס: חסר לוגיקה של משחק המחשב

### `POST /games/:id/end-turn` - סיום תור ללא העברה

אין גוף בקשה
מוודא שהמשחק פעיל ובשלב move

אין פעולת שחקן נוספת

השרת מפעיל תור מחשב מלא: חיזוק, תקיפה אפשרית והעברה אפשרית.

אם המשחק לא הסתיים, השרת מגדיל את מספר הסיבוב ומחזיר את השלב ל־reinforce.

תגובה תקינה: 200 OK במבנה תשובת הפעולה. playerEvent מתאר את העברת השחקן ו־computerEvents מכיל את הפעולות שביצע המחשב לפי סדר ביצוען.

סטטוס: חסר לוגיקה של משחק המחשב

## הפעלת הפרויקט

### 1. יצירת .env

יש ליצור קובץ:

```text
.env
```

לפי:

```text
.env.example
```

ולהכניס אליו את כתובת MongoDB.

### 2. הפעלת ה-Backend דרך Docker

מתיקיית הפרויקט:

```bash
docker compose up --build
```

ה-Backend זמין ב:

```text
http://localhost:3001
```
